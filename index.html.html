Qué es un error: sintaxis contra excepciones

Tarde o temprano, todo programa se enfrenta a situaciones inesperadas: la persona escribe texto donde se esperaba un número, un archivo no existe, se intenta dividir por cero. Si no las controlamos, el programa se rompe, muestra un mensaje técnico y se corta.

Manejo de errores: nos permite anticipar esos problemas y responder con elegancia, sin que el programa se caiga.

Conviene distinguir dos grandes familias de errores. La diferencia está en cuándo aparecen.

Errores de sintaxis. Son de escritura: el código está mal escrito y Python ni siquiera puede arrancar (por ejemplo, olvidar los dos puntos de un if).

Excepciones. Ocurren cuando el código es válido pero algo falla durante la ejecución. Estas son las que podemos manejar.

Errores de sintaxis: no se ejecuta ni una línea

Los errores de sintaxis ocurren cuando el código no sigue las reglas gramaticales de Python: paréntesis o comillas sin cerrar, palabras reservadas mal usadas, indentación incorrecta, dos puntos que faltan. Son los más fáciles de detectar, porque Python lee todo el archivo antes de empezar y ni siquiera intenta ejecutarlo.

if True
    print("¡Esto causará un error!")
  File "programa.py", line 1
    if True
           ^
SyntaxError: expected ':'
print("Hola)
  File "programa.py", line 1
    print("Hola)
          ^
SyntaxError: unterminated string literal (detected at line 1)

El ^ apunta al lugar donde Python se dio cuenta del problema: en el primero falta el : y en el segundo no se cierran las comillas.

Excepciones: el programa arranca y se cae en el medio

Con una excepción el código está bien escrito, así que Python lo empieza a ejecutar. El problema aparece recién al llegar a la línea que falla. Fijate que en este ejemplo la primera línea sí se imprimió:

nombre = "Ana"
print("Hola", nombre)
print(variable_inexistente)
print("Chau")

Cómo leer el mensaje

Este es el mensaje que aparece al ejecutar el programa de arriba. Se lee de abajo hacia arriba: la última línea te dice qué pasó y las de arriba, dónde pasó.

Hola AnaLo que se ejecutó antes del error.
Traceback (most recent call last):Empieza el informe del error.
File "programa.py", line 3, in <module>Dónde: archivo y número de línea.
print(variable_inexistente)La línea que falló.
^^^^^^^^^^^^^^^^^^^^La parte exacta (aparece en versiones recientes de Python).
NameError: name 'variable_inexistente' is not definedQué pasó: tipo de excepción + descripción.

"Chau" nunca se imprime: el programa se cortó en la línea 3. En estos ejemplos, la ruta del archivo aparece acortada a programa.py.

Los errores más comunes

Cada excepción tiene un nombre que dice qué salió mal. Si reconocés el nombre, ya sabés dónde buscar. Estas son las que vas a ver más seguido.

NameError: un nombre que no existe

Aparece cuando intentamos usar una variable, función o módulo que no ha sido definido previamente. Python no puede encontrar el nombre al que estamos haciendo referencia.

Causas frecuentes: el nombre está mal escrito, se usa antes de asignarle un valor, falta un import o se confundieron mayúsculas y minúsculas.

print(variable_inexistente)
NameError: name 'variable_inexistente' is not defined

Ojo: Python distingue mayúsculas de minúsculas. edad, Edad y EDAD son tres variables distintas.

TypeError: tipos que no se pueden combinar

Surge cuando intentamos realizar operaciones con tipos de datos incompatibles. Por ejemplo, no podemos sumar directamente un número con un texto.

"5" + 3
TypeError: can only concatenate str (not "int") to str
tiempo_en_minutos = "120"
tiempo_en_horas = tiempo_en_minutos / 60
TypeError: unsupported operand type(s) for /: 'str' and 'int'

"120" va entre comillas, así que es un texto aunque parezca un número.

ZeroDivisionError: dividir por cero

Ocurre cuando intentamos dividir un número por cero, una operación matemáticamente indefinida que Python no puede procesar.

Suele aparecer cuando el denominador es una variable, adentro de un bucle o cuando el número lo ingresa el usuario y nadie lo validó.

10 / 0
ZeroDivisionError: division by zero

IndexError: una posición que no existe

Aparece cuando intentamos acceder a una posición que no existe en una lista, tupla o string. Recordá que los índices en Python empiezan en 0.

frutas = ["Naranja", "Durazno", "Manzana"]   # posiciones 0, 1 y 2
print(frutas[5])
IndexError: list index out of range
palabra = "Hola"
print(palabra[10])
IndexError: string index out of range

ValueError: el tipo está bien, el valor no

Un valor del tipo correcto pero inadecuado: int() espera un texto, pero no cualquier texto: tiene que representar un número entero.

int("hola")
ValueError: invalid literal for int() with base 10: 'hola'
int("2.5")
ValueError: invalid literal for int() with base 10: '2.5'

Ojo: "2.5" es un número, pero no es entero, y int() lo rechaza igual. Por eso, cuando uses int(), el mensaje para el usuario tiene que pedir un número entero, no "un número".

KeyError: una clave que no está

Clave inexistente en un diccionario. Es el equivalente del IndexError para diccionarios.

precios = {"pan": 1500}
print(precios["leche"])
KeyError: 'leche'

try / except: atrapar una excepción

El código “riesgoso” (el que podría fallar) se pone dentro del try. Si ocurre una excepción, en lugar de romperse, Python salta al bloque except, que decide qué hacer.

Imagen mental: el try/except es como la red de seguridad de un trapecista. El artista intenta la pirueta (el try): si sale bien, la red no se usa. Si falla, la red lo atrapa (el except) y evita el desastre. El espectáculo continúa en lugar de terminar de golpe.

try:
    edad = int(input("Ingresá tu edad: "))
    print(f"El año que viene tendrás {edad + 1}")
except ValueError:
    print("Eso no es un número entero.")
  • Si la persona escribe un número entero, todo funciona y el except se ignora por completo.
  • Si escribe, por ejemplo, hola, int() falla y se lanza un ValueError. En ese momento se abandona el resto del try (el print del año no se ejecuta) y except ValueError atrapa justo ese error.

Capítulo 4 · Video 4 · Actividad II

Varios except y as

Una misma porción de código puede fallar de distintas maneras. Podemos escribir varios bloques except, uno por cada tipo de error, para responder de forma específica a cada uno. Python ejecuta el primero que coincida.

try:
    a = int(input("Numerador: "))
    b = int(input("Denominador: "))
    print(a / b)
except ValueError:
    print("Tenés que ingresar números enteros.")
except ZeroDivisionError:
    print("No se puede dividir por cero.")

Guardar el error con as

Al capturar una excepción podemos guardarla en una variable con as para ver su mensaje.

try:
    numero = int("abc")
except ValueError as e:
    print("Error:", e)
Error: invalid literal for int() with base 10: 'abc'

Con esa variable también se puede averiguar qué tipo de error ocurrió, usando type(e).__name__:

try:
    division = 12 / 0
except ZeroDivisionError as e:
    print("Ocurrió el siguiente error:", type(e).__name__)
Ocurrió el siguiente error: ZeroDivisionError

Varias excepciones en un mismo except

Si dos errores distintos se responden igual, no hace falta repetir el bloque: se escriben juntos, entre paréntesis y separados por coma.

for texto in ["8", "cero", "0"]:
    try:
        print(100 / int(texto))
    except (ValueError, ZeroDivisionError) as e:
        print("No se pudo:", type(e).__name__)
12.5
No se pudo: ValueError
No se pudo: ZeroDivisionError

Exception: la red para lo que no previste

Dentro de las excepciones múltiples se puede incluir except Exception as e: para aquellos casos donde el programa falla, pero la falla no se debe a ninguno de los errores listados en las excepciones anteriores.

numeros = [10, 20, 30]
try:
    posicion = int(input("Posición: "))
    print(numeros[posicion])
except ValueError:
    print("Tenés que ingresar un número entero.")
except Exception as e:
    print("Ocurrió el siguiente error:", type(e).__name__)
Posición: 7
Ocurrió el siguiente error: IndexError

Ojo con el orden: como Python ejecuta el primer except que coincide, y Exception coincide con casi todo, except Exception va siempre al final. Si lo ponés primero, los except específicos de abajo no se ejecutan nunca.

Capítulo 5 · Video 5 · Actividad II

else y finally

La estructura se completa con dos bloques opcionales:

else se ejecuta solo si no hubo ninguna excepción en el try. Sirve para separar la lógica exitosa.

finally se ejecuta siempre, haya error o no. Se usa para tareas de limpieza, como cerrar un archivo.

El try intenta; si hay error va al except, si no, al else; el finally corre en todos los casos.

try:
    numero = int(input("Ingresá un número: "))
except ValueError:
    print("No era un número.")
else:
    print(f"El doble es {numero * 2}")
finally:
    print("Gracias por usar el programa.")

Volver a pedir el dato: while True

Para no tener que volver a ejecutar el programa cada vez que aparece un error, se puede encerrar el try en un bucle while. El break va en el else: solo se sale del bucle cuando no hubo error.

while True:
    try:
        numerador = int(input("Numerador: "))
        divisor = int(input("Divisor: "))
        division = numerador / divisor
    except ValueError:
        print("Tenés que ingresar números enteros. Probá de nuevo.")
    except ZeroDivisionError:
        print("No se puede dividir por cero. Probá de nuevo.")
    else:
        print(division)
        break
    finally:
        print("Fin del intento.")
print("Listo.")

En azul, lo que escribió la persona. "Fin del intento." aparece en cada vuelta, incluso en la última, cuando el else ejecuta el break: el finally corre siempre.

Ojo: dentro de un while True, usá siempre un except con el tipo de error (except ValueError). Un except: sin tipo atrapa hasta el intento de cortar el programa con Ctrl+C, y el bucle no termina nunca.

raise y excepciones propias

Hasta acá atrapamos errores que lanza Python. Pero también podemos lanzar errores a propósito con raise, e incluso definir nuestras propias excepciones creando una clase que herede de Exception.

class SaldoInsuficiente(Exception):
    pass

def extraer(saldo, monto):
    if monto > saldo:
        raise SaldoInsuficiente("No hay saldo suficiente")
    return saldo - monto

try:
    nuevo_saldo = extraer(1000, 5000)
    print("Nuevo saldo:", nuevo_saldo)
except SaldoInsuficiente as error:
    print("Rechazado:", error)
Rechazado: No hay saldo suficiente
  • class SaldoInsuficiente(Exception): pass crea un tipo de error nuevo. Hereda de Exception, así que se comporta como cualquier otra excepción.
  • raise la lanza cuando la regla del problema no se cumple (sacar más de lo que hay).
  • El try llama a extraer con un monto demasiado grande, lo que dispara la excepción. El except la atrapa y, gracias a as error, puede mostrar el mensaje que le pusimos.

Buenas prácticas y cómo encarar el TP 8

Buenas prácticas. No uses except: a secas para atrapar “cualquier cosa” y seguir como si nada. Capturá los errores específicos que esperás; así no escondés errores reales y tus mensajes son útiles. Manejar errores no es disimularlos, es responder a ellos.

  • Sé específico con las excepciones: capturá tipos de errores concretos en lugar de usar un except genérico. Así es más fácil depurar y mantener el código.
  • Mantené el try chico: incluí solo el código que realmente puede fallar. Así es más fácil identificar dónde ocurrió el problema.
  • Dá mensajes claros: que le digan al usuario qué salió mal y cómo solucionarlo.
  • Documentá tus excepciones: explicá por qué manejás ciertos errores y qué alternativa le das al usuario cuando ocurren.
Evitá 
try:
    cantidad = int(input("Cantidad: "))
except:
    print("Error")
Preferí 
try:
    cantidad = int(input("Cantidad: "))
except ValueError:
    print("La cantidad tiene que ser un número entero.")
else:
    print("Pediste", cantidad)

El de la izquierda esconde cualquier problema detrás de "Error". El de la derecha dice qué pasó y qué hacer.
